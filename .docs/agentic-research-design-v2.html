Dokumen ini menjelaskan kondisi backend agent research saat ini per 24 April 2026: module, flow multi-turn, database persistence, integrasi Claude Agent SDK, Qdrant, Exa Websets, dan cara API digunakan oleh client.

Ringkasan Arsitektur Workflow API Chat Thread Database SDK Runner Tools Operasional

Ringkasan

Tujuan

Slice ini membuat platform backend untuk menjalankan research agent secara authenticated, menyimpan progress, chat thread, dan hasil secara durable, lalu mengekspos hasilnya lewat API.

Batas Scope

Implementasi ini backend-only. Tidak ada UI baru. Client bisa mulai menggunakan endpoint API untuk stream progress dan membaca hasil session.

Agent menggunakan Claude Agent SDK query() untuk setiap phase, Zod sebagai runtime validator, dan Drizzle/Postgres sebagai source of truth untuk session, messages, runs, events, evidence, dan claims.

Kondisi sekarang bukan lagi one-shot only. Endpoint awal POST /agents/research membuat turn pertama, sedangkan follow-up memakai POST /agents/research/:sessionId/messages dan menjalankan research workflow ulang di session yang sama.

Arsitektur Module

Module mengikuti convention API yang sudah ada: route hanya di index.ts, business logic di service.ts, database access di repository.ts, dan dependency injection lewat servicesPlugin.

Workflow Eksekusi

1. Create session

Client memanggil POST /agents/research. API membaca Clerk identity, resolve owned workspace, lalu membuat record agent_sessions dan agent_research_sessions. Prompt awal juga disimpan sebagai agent_messages role user turn 1.

2. Planner

Phase planner membuat research plan: researchQuestions, searchQueries, dan requiredEvidence.

3. Research loop

Agent menjalankan loop researcher dan critic. Mode standard maksimal 3 iterasi; mode deep maksimal 5 iterasi.

4. Synthesizer

Phase synthesizer membuat draft final answer, evidence items, dan claims yang terhubung ke citationKeys.

5. Citation audit

citation-audit.ts memvalidasi deterministically bahwa supported claim punya citation key dan citation key itu ada di evidence list.

6. Revision or final

Jika audit gagal, agent menjalankan synthesizer_revision satu kali. Jika tetap gagal, session disimpan sebagai failed tanpa finalAnswer. Jika lolos, session menjadi completed dan final answer disimpan sebagai agent_messages role assistant.

7. Follow-up turn

Client mengirim POST /agents/research/:sessionId/messages. Jika session tidak sedang running, API menyimpan user message baru, set session menjadi running, lalu menjalankan planner sampai final ulang dengan context thread sebelumnya.

API Surface

Endpoint Fungsi Response
POST /agents/research Membuat research session, menyimpan initial user message, dan menjalankan agent workflow. Request body: { prompt: string, depthMode?: "standard" | "deep" } text/event-stream berisi curated progress events.
POST /agents/research/:sessionId/messages Menambahkan follow-up message ke session yang sama dan menjalankan research workflow ulang. Request body: { message: string, depthMode?: "standard" | "deep" }. Jika depthMode kosong, API memakai depth mode session sebelumnya. text/event-stream. Jika session sedang running, response 409 dengan code agent_session_busy.
GET /agents/research/:sessionId Membaca durable session state yang authorized untuk workspace user. Status session, final answer jika completed, audit warnings, audit failures, messages, dan evidence summary.
GET /agents/research/:sessionId/events Membaca persisted event summary. Raw SDK payload tidak diekspos ke client. Array event curated dengan sequence dan phase.

Chat Thread dan Follow-up

Research agent sekarang memakai model chatbot-style multi-turn. Thread canonical disimpan di Postgres, bukan di SDK resume state. Alasannya: orchestrator menjalankan beberapa query() terpisah untuk phase planner, researcher, critic, synthesizer, dan revision.

Initial Turn

POST /agents/research membuat session dengan status running, membuat agent_messages user turn 1, lalu stream progress sampai terminal event. Saat sukses, assistant answer disimpan di agent_messages dengan status completed.

Follow-up Turn

Follow-up memuat original prompt, recent conversation messages, latest final answer, prior plan/synthesis/audit, evidence items, claims, dan user message terbaru. Context itu dipakai untuk research ulang di session yang sama.

Concurrency v1 sengaja strict: jika agent_sessions.status masih running, follow-up baru ditolak dengan 409 agent_session_busy. Belum ada queue untuk concurrent messages.

Database Persistence

Schema source of truth ada di packages/db/src/schema.ts. Migration agent utama dibuat di apps/api/drizzle/0003_natural_gertrude_yorkes.sql, lalu table chat thread ditambahkan lewat apps/api/drizzle/0004_bright_dracula.sql.

Session Tables

  • agent_sessions: root session, auth scope, status, final answer.
  • agent_messages: durable user/assistant thread per turn.
  • agent_research_sessions: research-specific plan, synthesis, audit.

Execution Tables

  • agent_runs: satu row per SDK phase run.
  • agent_events: raw SDK message internal dan curated event.

Research Artifacts

  • agent_research_candidate_sources
  • agent_research_evidence_items
  • agent_research_claims

Migration 0004_bright_dracula.sql saat ini hanya membuat agent_messages, foreign key, check constraint, unique (session_id, turn_number, role), dan index (session_id, created_at). Tidak ada destructive statement terhadap table lain.

Claude Agent SDK Runner

sdk-runner.ts adalah boundary untuk semua pemanggilan Claude Agent SDK. Ia bertanggung jawab membuat agent_runs, menjalankan query(), menyimpan setiap SDK message ke agent_events, lalu memvalidasi structured_output dengan Zod. 

query({
  prompt,
  options: {
    model,
    maxTurns,
    maxBudgetUsd,
    taskBudget,
    outputFormat: { type: "json_schema", schema },
    permissionMode: "dontAsk",
    allowedTools,
    mcpServers
  }
})

Model name, max turns, dan budget tidak di-hardcode di runner. Semua berasal dari AgentModelManager.getPhaseConfig().

Model Manager

Mode Research Iterations Researcher maxTurns Budget Source
standard 3 16 AGENT_STANDARD_MAX_BUDGET_USD
deep 5 32 AGENT_DEEP_MAX_BUDGET_USD

Default model semua phase adalah AGENT_DEFAULT_MODEL. Dengan desain ini, perubahan routing model per phase bisa dilakukan di satu tempat tanpa mengubah runner atau orchestrator.

Research Tools

Qdrant Tools

qdrant-tools.ts membuat in-process SDK MCP server. Collection yang digunakan: academic-paper-v1 dan academic-chunk-v1.

  • check_coverage
  • hybrid_search
  • get_chunk

Exa Websets Tools

websets-tools.ts menggunakan hosted MCP endpoint: https://websetsmcp.exa.ai/mcp via mcp-remote. Tool allowlist mengecualikan create_monitor supaya tidak ada background monitor lifecycle.

Authorization

Semua route agent memakai authIdentityPlugin. Service resolve user dan owned workspace dengan pattern yang sama seperti journals. Setiap session disimpan dengan workspaceId dan userId, lalu semua read memakai filter sessionId + workspaceId. Cross-workspace read akan menghasilkan agent_session_not_found.
