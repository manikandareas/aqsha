Peta fase implementasi

Fase A — merge duluan

Identitas statistik di chat (FE murni)

  • A.1 katalog display-meta di chat-core (label + kredit, 27 entri + profile + custom) + sync-test di services — pagar drift katalog
  • A.2 detail kind baru analysis / dataset-profile di timeline + TOOL_LABELS + heavy map (spinner + elapsed)
  • A.3 kartu run: running (copy bertahap utk uji berat) → struk (chip verdict dari DB) → error dengan konteks
  • A.4 kartu dataset: kolom + tipe + missing, parse defensif (zod, field opsional)
  • Klik struk dibelakangi guard → Fase A bisa merge sebelum panel ada
Fase B

Tab "Statistik" di side panel

  • B.1 mode { kind: "stats", runKey? } · URL s / s:<runKey> — mirror persis pola Sumber
  • B.3–B.4 data via ThreadPanelLookups (extend, bukan query baru) — urutan = urutan timeline (D5)
  • B.5 tab hidden saat belum ada hasil (pola Pratinjau)
  • B.6 StatsListPanel: agregat (list + chip verdict) ↔ scoped (render penuh StatsVizGroup, reuse)
  • B.7 scroll-to-message via data-message-id
  • B.8 aktivasi silang: struk & blok inline dapat tombol buka-panel
Fase C

Chip next-step + ekspor dari panel

  • C.1 peta statis per analysis id (ritual SKILL.md) — hanya run terakhir + settled; custom & Tier 3 tanpa saran; tap = prefill composer (OQ3: bahasa natural)
  • C.2 route GET /threads/:id/analysis-export?format=docx|xlsx — unduhan langsung, tanpa artifact (OQ1), tanpa debit
  • C.3 FE: mutation pola useDownloadThreadReferences, dropdown di panel, loading state jelas (sandbox ~1 menit)

Fase D — backlog (di luar scope sekarang)

  • D.1 variable-mapper khusus di ask_questions (dropdown per kolom dari profil dataset)
  • D.2 progress live di panel saat run berjalan (dari timeline, bukan DB) — dicicip di demo lewat tombol simulasi ▶
  • D.3 thumbnail figur di list agregat
  • D.4 ekspor per-run + .sav (butuh picker dataset)
  • D.5 panel Statistik di compact chat (workspace/explore)
