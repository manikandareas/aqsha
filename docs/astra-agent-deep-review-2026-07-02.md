## Hasil re-verifikasi (2026-07-02)

**64 temuan, 0 false alarm.** Setiap temuan ditelusuri ulang ke source aktual + `node_modules/@mastra/` terpasang. Semua klaim "primitive tersedia tanpa upgrade" (bagian E) terkonfirmasi ada di versi terpasang.

**3 temuan PARTIAL — nyata, tapi satu detail dikoreksi:**

- **DUR-5** — benar run `running` tak resume & poll tak berguna. Koreksi: "menyerah senyap setelah 8 error (~20s)" **hanya** saat `runById` throw (server down). Jika agent restart lalu server hidup lagi, `runById` sukses baca snapshot beku, `errors` reset ke 0, dan poll **loop selamanya** (shimmer macet permanen) — bukan menyerah.
- **DUR-6** — benar `queueMessage` tak dipakai & tak ada antrean. Koreksi: "pesan diam-diam hilang" **overstated** — composer sudah busy-aware (`canSend = … && !busy`), submit early-return saat busy; teks tetap tersimpan di input, tak lenyap. Gap sebenarnya = fitur queueing tak ada, bukan message loss.
- **IMP-13** — 2 dari 3 sub-klaim benar (`strip-mention-markers.ts:10` klaim strip history **faktual salah**; komentar `memory.ts:25` abai bobot tool payload). Sub-klaim `astra-lite.ts:62` tak terbukti menyesatkan — komentarnya wajar & `TokenLimiter` memang jalan per-step.

**Temuan yang ternyata LEBIH parah dari tulisan awal (di-_under_-state):**

- **SEC-1** — prasyarat exploit (token tanpa email claim) adalah **kondisi default** session Clerk (`packages/chat-core/src/index.ts:39` menandai email "best-effort, bukan klaim token standar"). Jadi broadly exploitable, bukan corner case. `mergeBodyRequestContext` (`@mastra/server` `chunk-XRE4KFIZ.js:88`) hanya blok key `mastra__`; `aqsha__email` lolos. Naikkan prioritas eksekusi ke paling atas.
- **CFG-5** — search **berbayar** (`external_search`, 2 kredit) bisa jalan **sebelum** gate billing `approve-plan` (satu-satunya titik debit). Plus `delete_artifact` (requireApproval-suspend) melanggar aturan repo sendiri (`tools/index.ts:61-64`) yang melarang suspend-tool dalam workflow-generate.
- **FE-1 / FE-2** — history fetch selalu pakai `ASTRA_AGENT_ID="astra-lite"`, jadi thread **Pro pun terpotong di 16 pesan** (bukan 32). Flip lite→pro saat refresh mid-run inilah yang bikin FE-2 (duplikasi teks) **deterministik**, bukan sekadar probabilistik.

**Nuansa mitigasi (tak membatalkan temuan):** CTX-2 cache `"failed"` per-cacheKey expire 12 mnt (retry per query unik setelah TTL, tapi silence + charge-tanpa-refund tetap nyata); CFG-7/CFG-9 sebagian "defended" oleh rationale terdokumentasi (`citation_verify` 0-kredit; debit turn aman via replay buffer) — risiko laten ke path masa depan; FE-10 landmine laten (Hono tak kompres by default, semua call site GET/POST).
